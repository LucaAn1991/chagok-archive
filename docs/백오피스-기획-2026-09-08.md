# 차곡 백오피스 기획 — 통합본

> **상태: 카테고리별 검토 완료 (09-08 가영 님 확정) · 팀 공유 전.**
> 구현 착수 전 §7(팀 요구사항)과 §9(미결)를 팀과 맞춘다.
>
> 결정 배경 — **운영자에 비개발자가 포함된다**(가영 님 포함). Firebase 콘솔+터미널
> 스크립트 방식은 운영 행위마다 개발 가능한 사람을 거쳐야 해 성립하지 않고, 콘솔 직접
> 수정은 데이터 짝 규칙(status↔publishedAt 등)을 지켜주지 않아 위험하다. 판단 기준은
> 출시 일정이 아니라 **서비스 완성도**다.

---

## 1. 운영 항목 분석 (요약)

코드·DB 분석으로 찾은 "운영자가 처리해야 할 상황" 7개. 각 항목이 어느 화면으로
해결되는지 표시한다.

| # | 상황 | 핵심 문제 | 해결 화면 |
|---|---|---|---|
| 1 | AI 생성 실패·폴백 급증 | 기록 자체가 없어 품질 저하가 무감지 진행 | 생성 실패 큐 · 대시보드 |
| 2 | 외부 서비스 상태 어긋남 | Anthropic 키 누락 시 **목 모드 조용 전환** · GPTProto 크레딧 소진 · Pexels 한도 | 대시보드 상태등 |
| 3 | 비용 폭주·어뷰징 + 한도 CS | 사용자별 호출 기록 없음 — 청구서로야 발견 | 회원 상세 · 대시보드 |
| 4 | 문의 대응 (조회·복구) | 콘솔 JSON 해석은 비개발자 불가, 직접 수정은 집계 파괴 위험 | 회원 상세 · 문의 큐 |
| 5 | 탈퇴 실패 잔여물 | Auth/Firestore/Storage 3자 불일치 — 실패가 기록 안 됨 (법적) | 탈퇴 실패 큐 |
| 6 | 긴급 차단 | 수단이 없음 — 재배포뿐 | 설정 > 기능 스위치 |
| 7 | (낮음) 재동의·Storage 누적 | 재동의는 코드화됨 · 용량은 월 1회 확인 | 설정 > 정책 문서 |

**첫 번째 처리 큐 = 생성 실패·폴백 큐** — 본질(제작이 끊기지 않음) 직결 · 매일 발생
가능 · 조치가 명확(재생성/장애 확인/긴급 스위치).

## 2. 카테고리별 확정 사항

### ① 콘텐츠/데이터 관리
차곡은 운영자 공급 콘텐츠가 0인 서비스(콘텐츠는 사용자+AI가 만든다) → 신설 결정.
- **공지사항** — 등록/수정/숨김/삭제, `level: normal|banner`(banner는 홈 상단 1줄,
  최신 published 1건만)
- **FAQ** — 등록/수정/순서변경/숨김. 문의의 1차 방어선
- **긴급 안내 문구** — 기능 스위치가 꺼졌을 때 사용자 화면 문구
- **템플릿 진열 관리** — 우리의 상품 카탈로그. 노출/숨김·순서·기본 지정·이름 수정
  (코드는 "그리는 법"을 유지, Firestore에 "진열 속성"만 얹어 병합). **숨김은 신규
  선택만 막는다 — 기존 카드의 렌더는 불변.** 신규 템플릿 등록은 코드 8곳 결합이라
  데이터화 리팩토링 선행 필요(창현 님 협의, §9)
- 상태값: 공지·FAQ `hidden | published` 2개 — hidden이 임시저장 겸함. 실삭제 허용
- 제외: 상품·이벤트 배너(해당 없음), 랜딩 카피(개발 흐름으로 충분),
  약관 본문(→⑤로 이관)

### ② 사용자/회원 관리
- **회원 목록**: 이메일(마스킹)·닉네임·가입일·온보딩 여부·최근 로그인(Auth)·상태·주간
  목표. 검색(이메일/닉네임/uid)·필터(상태·온보딩·기간)·정렬(가입일↓ 기본)
- **회원 상세**: 머리에 «이 사람의 차곡 상태»(주간 목표 대비 발행·잔고 보유) → 기획·
  카드 목록 → 동의 이력 → 사용량 → 관리 기록 탭. 조치: 정지/해제 · 한도 리셋 ·
  카드 복구(짝 규칙 자동) · 탈퇴 대행(admin 경로 신설 필요)
- **상태 규칙**: `활성 ↔ 정지(사유 필수)`. 진실은 Auth `disabled`, 사유·이력은
  admin_logs. 정지 시 토큰 강제 만료(revoke) 동반. 탈퇴=부재(실삭제 유지). 휴면 제외
- **마스킹·열람**: 목록 이메일 마스킹, 상세 전체 표시. **대화 내용·업로드 사진은 기본
  접힘 + «열람» 버튼 + 열람 기록**(사유 필수) — "운영자여도 상시 보지 않는다"
- **인앱 문의함** (이메일 아닌 이유: 맥락 자동 첨부·상태 관리·유저 상세 연결):
  `inquiries` — 유형·본문·`open→answered`·답변{본문·시각·관리자}. 사용자 화면은
  설정>문의하기+내역(FAQ와 같은 자리), 답변 인지는 v1 앱 내 표시점(발송 알림은 ③
  인프라 후). 추가 문의는 새 글(스레드 없음). 신고 기능 = 해당 없음(공개 지면 없음)

### ③ 마케팅/프로모션
차곡의 마케팅 실체 = **라이프사이클 메시징**(습관 서비스에서 알림은 제품 약속의 이행,
덱 로드맵 MLP «캘린더 알림»과 동일).
- **알림 4종**: 발행일 리마인드 · 캘린더 잔고 소진 · 놓친 카드 · 문의 답변.
  채널은 이메일 우선(모바일 웹 — iOS 푸시 제약, 이메일은 전원 보유)
- **백오피스**: 유형별 on/off · 템플릿 문구 편집 · 발송 이력 · 수동 전체 발송(동의자)
- **마케팅 수신 동의** 신설 — 서비스 알림(동의 불요)과 광고성(사전 동의 필수)을
  처음부터 구분. consents 확장 + 설정 토글 (→⑤ 방침 개정 목록)
- **유입 채널 기록** — 가입 시 UTM 저장(④ 유입 분석의 재료)
- 제외: 쿠폰/할인(결제 없음 — 수익화 시 차곡식 쿠폰은 **한도 확장권** 메모),
  이벤트 배너(공지 배너로 충분), 웹푸시(이메일 정착 후), 광고 타겟팅(방침 선언과 충돌)

### ④ 대시보드/분석
운영 대시보드(30초 판정+액션)와 분석(왜?)을 분리. **백오피스 = 운영 대시보드.**
- **3층 구성**: ❶즉시 조치 — 미처리 문의·생성 실패·탈퇴 실패·외부 API 상태등(목 모드
  =빨간불)·스위치 상태, 클릭 시 해당 큐로 ❷오늘의 건강 — 가입·활동·확정·제작·발행·
  비용, **최근 7일 평균 대비 ▲▼** ❸추이 — 일간 30일 그래프(가입·잔고·발행·폴백률·
  비용) + 주간 표(북극성·가드레일)
- **계산 방식**: 액션 카운트·오늘분 = 실시간 / 추이·잔고·북극성 = **`metrics_daily`
  일일 집계**(시점 상태는 그날 안 찍으면 재구성 불가 + distinct 사용자 세기는 전체
  스캔이라 매번 계산 낭비). 오늘 점만 실시간으로 얹음
- **외부 도구 분담**: 로그인 전(방문·유입·UTM 전환) = **GA4 채택**(자체 구현 낭비 +
  events 「랜딩→가입」 구간 대체 — 방침 고지 필요 →⑤) / 주간 리뷰 = 추이+CSV 내보내기
  / 코호트 심사 = 일회성 스크립트. Amplitude·BigQuery는 v2 재검토
- 템플릿 지표 상세 1장(선택 수·재생성률·폴백률)

### ⑤ 설정/정책
기준: **바꾸는 사람이 운영이면 DB, 코드 동작과 결합이면 코드.**
- `ops/config` — 레이트리밋 수치·카드 상한 8·배치 4주·연락처·SEO(서비스명·소개·OG).
  캐시 5분
- `ops/flags` — 기획 on/off·이미지 생성 on/off·안내 문구. **서버 캐시 60초**(사고 시
  1분 내 전파)
- `legal_docs/{문서}-{버전}` — 약관·방침을 DB 불변 버전으로 이관.
  `draft → scheduled(게시·고지) → effective(시행)`, **effective는 수정 불가**(개정=새
  버전), 사전 고지 기간(7일/불리한 변경 30일)을 화면 검증으로 강제, 시행 시 재동의
  흐름(§6 법적 재개봉) 자동 발동. versions.ts 상수 비교 → DB 버전 비교로 교체
- SEO·정책 페이지는 저장 시 캐시 재생성(revalidate)으로 즉시 반영
- 코드에 남김: 기술 상수(파일 크기·캐시), AI 모델명(교체=검증=배포)
- **다음 방침 개정(1.1)에 묶을 목록**: GA4 고지 · 마케팅 수신 동의 · 운영자 열람 고지
  · «ooo» 실명·시행일(찬영 님)

### ⑥ 시스템/보안
- **접근 권한**: 단일 admin 역할(Auth 커스텀 클레임 `admin: true`), /admin 전체 서버
  검증+noindex. 역할 세분 대신 **위험 행위는 마찰로 방어**(사유 입력+재확인 — 탈퇴
  대행·긴급 스위치·정책 게시). **부여/회수는 터미널 스크립트만**(화면에 두면 계정 탈취
  시 권한 확산) — 백오피스엔 관리자 목록 읽기 전용
- **감사 로그 `admin_logs`**: 스키마 = at · actorUid · actorEmail(복사 저장) · action ·
  targetType · targetId · reason(민감 열람·정지·스위치·정책 게시·수동 발송·권한은 필수)
  · before/after(설정·콘텐츠류만 — **사용자 개인정보 값은 절대 안 담음**) · ip · UA.
  인덱스 4: (at) (actorUid,at) (targetType,targetId,at) (action,at).
  **불변** — 수정·삭제 API 없음+클라이언트 쓰기 차단. 보존 1년 제안(방침 «부정 이용
  기록 1년»과 정합, 정기 삭제)
- **수집**: 모든 admin API가 **`withAdmin` 공용 래퍼 한 층**을 통과(클레임 검증→실행→
  자동 기록) — 빠지는 라우트가 구조적으로 불가능. 회원 목록·상세 «조회»는 기록 안 함
  (소음) — 민감 경계는 «열람 버튼 안쪽»
- **로그인/로그아웃**: 토큰의 인증 시각(auth_time)이 갱신되면 `admin.login` 기록.
  로그아웃은 명시 버튼만(브라우저 닫기는 웹 한계 — 마지막 활동 시각으로 대체)
- **안전망**: Firestore 일일 자동 백업 — 구현 전 최우선으로 켠다

## 3. 화면 지도 (/admin)

```
/admin
├─ 대시보드 (홈) ── 3층: 조치 줄 · 오늘 · 추이        [④]
├─ 처리 큐
│   ├─ 문의 큐 (open 기본 · 오래된 순 · →회원 상세)   [②]
│   ├─ 생성 실패 큐 (신규→확인→조치완료 · 재생성)     [분석#1]
│   └─ 탈퇴 실패 큐 (파기 재실행)                     [분석#5]
├─ 회원
│   ├─ 목록 (검색·필터·정렬)                          [②]
│   └─ 상세 (상태 요약 · 활동 · 조치 4종 · 관리 기록) [②⑥]
├─ 콘텐츠
│   ├─ 공지 관리 · FAQ 관리                           [①]
│   └─ 템플릿 진열 (+ 템플릿 지표 상세)               [①④]
├─ 알림 (스위치 · 템플릿 · 이력 · 수동 발송)          [③]
├─ 설정 (기본 정보 · 운영 한도 · 기능 스위치 · 정책 문서) [⑤]
└─ 시스템 (감사 로그 탐색 · 관리자 목록[읽기전용])    [⑥]
```

사용자 쪽 신설 지면: 설정>공지사항·FAQ·문의하기/내역, 홈 배너 1줄, 알림 수신 설정.
(최소 구현 후 다듬기는 창현 님 — DESIGN.md 준수)

## 4. 공통 기반 4종 (화면보다 먼저)

| 기반 | 내용 | 쓰는 곳 |
|---|---|---|
| admin 권한 | 커스텀 클레임 + `withAdmin` 래퍼(검증+로깅) + 부여 스크립트 | 전 화면 |
| 감사 로그 | `admin_logs` + 공용 기록 함수 | 전 화면 |
| 정기 실행 | 매일 아침 KST 크론 1개 | metrics_daily 집계 · 리마인드 발송 · 로그 보존 삭제 |
| 이메일 발송 | 외부 발송 서비스 (§9 — 선정 필요) | 알림 4종 · 수동 발송 |

## 5. 신설 데이터 총목록

| `legal_docs` | 약관·방침 불변 버전 | ⑤ |
| `admin_logs` | 감사 로그 (append-only) | ⑥ |
| `metrics_daily` | 일일 지표 스냅샷 | ④ |
| `notifications` | 발송 기록(중복 방지·이력) + 유형별 템플릿 | ③ |

**기존 문서에 추가하는 필드**

| 필드 | 위치 | 쓰임 (겹치는 곳 주목) |
|---|---|---|
| 사용량 카운터 (일별 aiCalls·imageGens·재생성) | users | **레이트리밋(찬영)** + 어뷰징 감지 + 대시보드 비용 + 템플릿 재생성률 |
| `renderedBy: "ai"|"fallback"` + 실패 사유 | cards.slides | 생성 실패 큐 + 폴백률 경보 + 템플릿 지표 |
| 마케팅 수신 동의 | consents·users | ③ 알림 + ⑤ 방침 |
| UTM 유입 채널 | users | ④ 유입 분석 |

## 6. 구현 우선순위 (제안)

의존 순서 — 안전장치는 전제라 먼저, 데이터 기록은 쌓여야 가치라 다음.

1. **기반·안전**: Firestore 백업 켜기 → admin 클레임+`withAdmin`+`admin_logs`+부여
   스크립트 → 긴급 스위치(`ops/flags`)+`ops/config`
2. **감지 데이터**: 사용량 카운터(찬영 님과 규격 합의)·`renderedBy`·탈퇴 시도 기록 →
   대시보드 홈 + `metrics_daily` 집계(크론 신설)
3. **CS**: 회원 목록/상세+조치 4종 → 문의함(사용자 지면+큐) → 생성 실패 큐·탈퇴 실패 큐
4. **콘텐츠·정책**: 공지/FAQ+사용자 지면+홈 배너 → 템플릿 진열 → 설정 화면 +
   `legal_docs` 이관(재동의 연동 포함)
5. **알림·분석**: 이메일 인프라+알림 4종+수신 설정 → GA4 삽입 → CSV 내보내기 ·
   템플릿 지표 상세

## 7. 팀 요구사항 (전달용)

**찬영 님 (레이트리밋·수익화)**
- 한도 수치를 상수가 아니라 `ops/config`에서 읽게 (백오피스 튜닝 전제)
- 카운터 규격 공유 — 사용량 카운터 하나가 레이트리밋·어뷰징 감지·비용 대시보드·
  템플릿 재생성률 4곳에 쓰인다. 규격을 같이 정하고 한 번만 만들기
- 방침 «ooo» 실명·시행일 → `legal_docs` 이관 시점과 맞추면 한 번에 처리
- (수익화 시) 결제·환불 화면은 /admin에 자리만 잡아둠

**창현 님 (개발·UX/UI)**
- 템플릿 신규 등록의 데이터화 리팩토링 협의 (지금은 코드 8곳 결합 — 진열 관리만 먼저)
- 사용자 쪽 신설 지면(공지·FAQ·문의·알림 설정·홈 배너) 최소 구현 후 다듬기 인계
- F9 발행 확인·홈 자동 이월과 «놓친 카드 알림»의 관계 정리

## 8. 지표-체계 문서 개정 포인트

`docs/지표-체계-2026-09-08.md` §5 «단계 0 = 스크립트+스프레드시트»는 백오피스 결정
전의 설계 → **«metrics_daily 집계 + 백오피스 대시보드»로 개정**. 일간 경보 3종은
대시보드 ❶❷층에, 주간 판정은 ❸층+CSV로 흡수. 랜딩→가입 구간은 GA4로 대체되어
자체 events 필요분이 다시 줄어든다. (문서 개정은 팀 확정 후 일괄)
